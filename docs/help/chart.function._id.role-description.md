# Role description

The full AiMS role description for this seat — Position Summary,
Core Success Outcomes, Success Measures, Key Responsibilities,
Decision Rights, Strengths & Expertise, Competency Indicators,
Qualifications, and Why This Role Matters — assembled from what's
on the function's page and a one-shot AI draft of the connective
prose. It's the doc you send to a candidate, keep in the offer
packet, or print for a coaching conversation.

## How it's built

- **Chart data flows in directly**: Job Title comes from the
  function name. Success Measures, Key Responsibilities, Decision
  Rights, and Competency Indicators all come from what's on
  `/chart/function/[id]`. To change any of them, edit at the
  source on the function's page — the RD refreshes on the next
  visit or when someone hits Regenerate.
- **The prose sections are drafted for you**: Position Summary,
  the "why this matters" and "values connection" under each
  outcome, per-responsibility strategic context, Strengths &
  Expertise, Qualifications, and Why This Role Matters are
  generated by an AI pass through the AiMS voice — positively
  framed (moves toward what the seat is chasing), values-aware
  (bolds any company core values it names), and never mentions a
  specific person by name since the doc describes the seat, not
  the incumbent.
- **The doc is cached** so second-and-later visits are instant.
  It auto-regenerates when any chart entity on the function has
  been edited since the last generation. Foundation edits
  (company purpose, values, differentiators) don't auto-invalidate
  — hit **Regenerate** when you want a fresh pass to reflect them.

## Common things people do here

- **Create or view the RD** — the readiness card at the bottom of
  the function page reads "Create role description →" until a
  cached doc exists, then "View role description →". First visit
  runs the generation and shows a "Assembling the role
  description…" skeleton while it works. Subsequent visits are
  instant.
- **Edit the free-form prose** — Position Summary, Why This Role
  Matters, and each Qualifications sub-field (Experience,
  Education, Certifications) carry an Edit button. Click, tweak
  the wording in the textarea, Save. An "Edited" pill + "Restore
  generated" link appears when a section carries a manual
  override; Restore clears the override and the AI version comes
  back. **Edits survive regeneration** — the cache preserves your
  overrides on top of any fresh draft. Every other section on the
  RD is either pulled from chart data (edit at the source on the
  function page) or refreshed by hitting Regenerate.
- **Regenerate** — admin-only pill in the toolbar. Clears the
  cache and reruns the AI draft from scratch (keeps any Position
  Summary / Why edits, since those live on user overrides).
  Useful after a foundation edit, or when the voice needs a
  refresh.
- **Download .docx** — primary pill in the toolbar. Streams a
  proper Word file with heading hierarchy, native bullets,
  numbered badges on every list, italic subtitle, and page
  numbers in the footer. Opens cleanly in Word, Pages, and
  Google Docs.
- **Publish version** — snapshots the current merged document +
  overrides into an immutable version (v1, v2, v3…). Add an
  optional note if you want a paper trail on what changed. Each
  version is browseable from the Versions section at the bottom
  of the page, with its own docx URL that stays byte-stable
  forever.

## Access

- **System admins, company admins, and AiMS Guides** on this
  company can view, edit prose sections, publish versions,
  regenerate, and delete versions.
- **Everyone else on the company** can view the assembled RD
  (read-only) and download any published version's .docx.
- The RD generator has to be enabled for the company (Company
  settings → Features → *Role Descriptions*). If the flag is
  off, the RD readiness card on the function page and this
  entire route are hidden.

## Heads-up

- **The AI draft is a draft.** Read it before you send it
  anywhere — the AiMS voice prompt gets it 90% of the way but
  won't catch every company-specific nuance.
- **Sub-areas on Key Responsibilities aren't shown here.** Those
  live on the inline R&R list on the function page where they're
  a working reference; the RD reads cleaner without them.
- **Deleted versions are gone.** Version delete is permanent —
  the snapshot goes with it, though other versions and the
  current draft are unaffected. Publish a fresh version any time
  to reset.
