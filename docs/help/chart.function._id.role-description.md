# Role description

The full AiMS role description for this seat — Position Summary,
Critical Success Factors, KPIs, Key Responsibilities,
Decision Rights, Strengths & Expertise, Competency Indicators,
Qualifications, and Why This Role Matters — assembled from the
function page plus a generated draft of the connective prose.
It's the doc to send a candidate, put in an offer packet, or use
in a coaching conversation.

## What you can do here

::: role team_member
As a team member, you can:

- **View the assembled RD** — everyone in the company can read
  the current draft once the function has enough content on it.
- **Download the .docx** — the *Download* pill streams a proper
  Word file (heading hierarchy, bullets, numbered badges, italic
  subtitle, page numbers). Opens cleanly in Word, Pages, and
  Google Docs.
- **Browse published versions** — the Versions section at the
  bottom lists every published snapshot; each has its own
  byte-stable .docx URL.
:::

::: role company_admin,aims_guide,system_admin
As an admin or guide, you can also:

- **Edit the free-form prose** — Position Summary, Why This Role
  Matters, each Qualifications sub-field (Experience, Education,
  Certifications), and each Strengths & Expertise sub-field
  (Technical / Strategic / Interpersonal as lists; Ownership as
  a paragraph) carry an Edit button. An *Edited* pill +
  *Restore generated* link appears when a section carries a
  manual override. **Edits survive regeneration.**
- **Regenerate** — clears the cache and reruns the draft from
  scratch (user overrides are preserved). Useful after a
  Foundation edit or when the voice needs a refresh.
- **Publish a version** — snapshots the current merged document
  plus overrides into an immutable version (v1, v2, v3…). Add
  an optional note. Each version has its own permanent .docx URL.
- **Delete a version** — permanent. Other versions and the live
  draft are unaffected.
:::

## How the doc is assembled

- **Chart data flows in directly** — Job Title comes from the
  function name; Critical Success Factors with their KPIs, Key Responsibilities, Decision
  Rights, and Competency Indicators come from
  `/chart/function/[id]`. To change any of them, edit at the
  source on the function page.
- **Prose sections are drafted for you** — Position Summary, the
  *why this matters* and *values connection* under each outcome,
  per-responsibility strategic context, Strengths & Expertise,
  Qualifications, and Why This Role Matters are drafted in the
  AiMS voice: positively framed, values-aware (core values are
  bolded when named), never mentions a specific person by name.
- **The doc is cached** so second-and-later visits are instant.
  It auto-regenerates when any chart entity on the function has
  been edited since the last generation. Foundation edits
  (company purpose, values, differentiators) don't auto-invalidate
  — hit *Regenerate* when you want a fresh pass to pick them up.

## How to publish a version

1. Get the current draft into a shape you're happy with — edit
   any prose sections that need tightening.
2. Click *Publish version* in the toolbar. Add an optional note
   for the paper trail (what changed, why).
3. The snapshot lands in the Versions section at the bottom with
   its own permanent .docx URL.

## Common questions

**Why can't I see this page even though the RD readiness card
was there?** The RD feature has to be enabled for the company
(Company settings → Features → *Role Descriptions*). If it's off,
the entire route is hidden.

**A section isn't showing up.** Sections with no content are
hidden from the render. The banner at the top counts how many of
the readiness gates are met.

**Sub-areas on Key Responsibilities are missing.** By design —
those live on the inline R&R list on the function page as a
working reference. The RD reads cleaner without them.

**Is the AI draft ready to send?** Read it before you send it
anywhere. The AiMS voice prompt gets it 90% of the way, but
won't catch every company-specific nuance.
